完成 <a href="./build-sample.html" target="_blank">编译 Sample</a> 后，可运行示例程序，验证设备接入与数据上报流程。示例提供四个可执行程序：

| 程序 | 用途 |
|:---|:---|
| dock_quickstart | 最小示例，用于快速验证接入链路 |
| dock_sample | 机库（dt5）单设备交互示例，用于逐项调试机库功能 |
| rid_sample | RID（dt7）单设备交互示例，用于调试 RID / ADS-B 上报 |
| dock_cli | 全功能交互示例，先选择设备身份，再进入对应功能菜单 |

host 编译产物位于 `build/` 目录，aarch64 交叉编译产物位于 `build-aarch64/` 目录。

## 运行前准备

运行示例程序前，请完成以下准备：

1. **确认网络连接**：确认 O4 地面站与运行示例的设备在同一网段，网络配置见 <a href="./environment-prepare.html" target="_blank">环境搭建</a>。示例会通过 UDP `18830` 广播自动发现 Broker 地址；发现失败时，使用编译期配置的 `DOCK_BROKER_FALLBACK_IP`。
2. **确认凭据配置**：确认 `app_id`、`app_key`、`app_license` 与设备标识（`device_id`）已在编译时传入。示例工程默认使用设备 SN 作为 `device_id`。
3. **确认 aarch64 依赖库位置**：在 aarch64 目标板上运行时，可执行文件的 RPATH 为 `$ORIGIN/../lib`。请将 `third_party/aarch64-linux-gnu/lib/*.so` 拷贝到与 `bin/` 同级的 `lib/` 目录下。临时验证时，也可通过 `LD_LIBRARY_PATH=<so目录>` 指定依赖库目录。

如需临时切换设备身份或 Broker，可使用环境变量覆盖编译期配置，无需重新编译：

```bash
DOCK_DEVICE_SN=xxx DOCK_RID_SN=yyy DOCK_BROKER_IP=192.168.50.10 DOCK_BROKER_PORT=1883 ./build/dock_cli
```

## 快速验证

运行 `dock_quickstart`，验证设备能否正常接入 DJI 地面站：

```bash
./build/dock_quickstart
```

程序会依次完成：

1. **连接地面站**：自动发现 Broker 地址，未发现地址时使用回退地址。
2. **上报能力集**：声明设备类型，示例默认以机库（dt5）接入。
3. **执行一次操作**：下发一次充电命令（`charge_open`），验证功能接口是否可用，随后断开退出。

正常情况下，日志中会出现以下关键信息：

```text
[discover] listening on UDP 18830 (timeout=15000ms) ...
[discover] -> broker ip=192.168.50.10
[session] connecting 192.168.50.10:1883 (sn=你的设备SN) ...
[session] connected
  <report capability_report dt5 device_type=5> topic=thing/product/<account>/state rc=0
```

若程序打印 `[session] connected` 并正常退出（返回值 0），即表示接入链路已打通。

`dock_quickstart` 为最小接入流程，能力集上报采用异步发送方式。日志中的 `rc=0` 表示消息已发出，不表示网关已接受能力集。若需确认能力集上报回执，请使用 `dock_sample` 或 `dock_cli`，或在自定义代码中调用 `auth_report_capability_dt5_sync()`。

## 单设备调试

若仅调试一种设备类型，可运行对应的单设备示例。`dock_sample` 与 `rid_sample` 均会在连接成功后自动上报能力集，并等待能力集回执。正常情况下，日志中会出现以下信息：

```text
  <capability_report ack> success result=0
```

### dock_sample（dt5）

运行 `dock_sample`：

```bash
./build/dock_sample
```

菜单覆盖以下功能：

- 开机与充电：`drone_open`、`drone_close`、`charge_open`、`charge_close`
- 参数与固件：`get_tsl`、`set_tsl`、`set_work_mode`、`get_network`、`set_network`、`get_sdr`、`set_sdr`、`set_cloud`、`org_bind`
- 周期轮询：每 2s 执行一轮 `get_tsl`，也可选择叠加 `set_tsl`
- 起降协同：`takeoff_prepare`、`takeoff_end`、`landing_prepare`、`landing_end`、`abnormal_recovery` 进度上报
- 服务自检：回放 5 条入向 service 请求，验证 handler 注册是否正确

菜单项带 `*` 标记时，程序会逐个提示输入参数；直接按回车使用默认值或跳过该参数。

### rid_sample（dt7）

运行 `rid_sample`：

```bash
./build/rid_sample
```

菜单覆盖 `rid_infos` 单次上报、`adsb_infos` 单次上报，以及 RID / ADS-B 周期上报启停。周期上报每 2s 批量刷新一次，并遵守 5Hz 限频要求。

## 全功能调试

`dock_cli` 为两级菜单，一次只连接一个设备身份。运行后，先选择机库（dt5）或 RID 设备（dt7），程序会按所选身份完成连接、上报对应能力集并校验回执，然后进入对应功能菜单。退出子菜单时，当前身份会断开连接。

```bash
./build/dock_cli
```

设备身份选择菜单如下：

```text
===== Select connecting device identity (this CLI connects one at a time) =====
   1  third-party dock device (dt5)
   2  RID device              (dt7)
```

dt5 子菜单与 `dock_sample` 功能一致，dt7 子菜单与 `rid_sample` 功能一致。两个设备身份分别构建会话参数，并使用各自的 `device_id` 与账号。

## 报文日志

联调排查时，可开启报文日志查看实际收发的 JSON 消息。开启方式如下：

**方式一：运行中切换**

`dock_sample`、`rid_sample`、`dock_cli` 均支持在运行中按 `w` 切换报文日志开关。

**方式二：启动时使用环境变量**

```bash
THING_MODEL_LOG_LEVEL=debug ./build/dock_cli 2>&1 | grep -E 'PUB|RCV'
```

同一条请求（`PUB`）与回复（`RCV`）的 `tid` 一致，表示该轮请求与回复配对成功；若 `tid` 不一致或未收到回复，通常表示消息未送达或等待超时。

各功能的完整 Topic、payload 与字段说明详见 <a href="../api-reference/rid.html" target="_blank">RID 设备</a>、三方机库设备（<a href="../api-reference/dock/charging.html" target="_blank">开机充电</a>、<a href="../api-reference/dock/flight.html" target="_blank">起降协同</a>、<a href="../api-reference/dock/dock-config.html" target="_blank">机库配置</a>、<a href="../api-reference/dock/thing-model.html" target="_blank">参数配置</a>）等 API 介绍章节。

## RID / ADS-B 上报注意事项

调试 RID / ADS-B 上报时，请注意以下事项：

1. ADS-B 的 `speed` 线上单位为 km/h，FlightHub 2 会将该值除以 3.6 后按 m/s 显示。`dock_cli` 在输入 ADS-B 速度后会回显换算结果，例如输入 `941` 时会提示 `FlightHub 2 will display 261.4 m/s`。
2. 周期上报会覆盖手动单次上报的值。周期线程每 2s 刷新一次，本周期缓存为空时会重发上一次单次上报的目标（示例没有真实雷达源）。因此，在周期上报开启期间手动单次上报新值后，2s 后可能会被上一次目标的重发覆盖。调试参数时，建议先使用菜单 `33` 停止周期上报，或将周期上报作为稳定数据源单独观察。
