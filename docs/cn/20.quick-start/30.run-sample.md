## 运行前准备

- 确认 O4 地面站与运行示例的设备已接入同一局域网，网络配置见 <a href="./environment-prepare.html" target="_blank">环境搭建</a>。
- 确认已在 `include/mqtt/app_info.h` 填入 `app_id`、`app_key`、`app_license`、`device_id` 并重新编译。

## 运行示例

在编译产物目录执行：

```bash
./rid_report_demo
```

程序启动后会依次：

1. **检查开发者信息**：若 `app_info.h` 中仍为占位符，程序将提示需填写凭证。
2. **选择 Broker 地址来源**：程序提示选择获取 Broker 地址的方式（详见下方说明）。
3. **连接 MQTT 并等待结果**：连接成功时打印 `Connected.`（对应 `CONNACK=0`）；连接失败时将提示在后台持续重试。
4. **自动上报能力集**：连接成功后，示例立即向 `state` Topic 上报能力集（`device_type=7`）。在 `state_reply` 中收到 `result=0` 即表示接入成功。
5. **显示交互菜单**：菜单顶部显示当前连接状态。

```
========== ESDK V2 Sample ==========
 Status: [Connected]
-------------------------------------
 [1] RID device
 [q] Quit
=====================================
```

### Broker 地址选择

启动时程序会提示选择 Broker 地址的获取方式：

```
==== MQTT Broker setup ====
  [1] listen UDP 18830 until a valid broadcast arrives
  [2] skip discovery, use default 192.168.50.10:1883
select [1/2]:
```

- `[1]` 监听 UDP `18830`，等待 O4 地面站广播并自动解析出 Broker IP。适用于路由器组网等 IP 不固定的场景。收到广播后日志会打印解析结果，例如：

  ```
  [discover] -> valid: id=BMGDNAB0010122 name=O4_Ground_Station ip=192.168.50.10 seq=270
  ```

- `[2]` 跳过发现，直接使用默认地址 `192.168.50.10:1883`。适用于 LAN 口直连，Broker 地址固定的场景。

广播报文格式与发现机制详见 <a href="./environment-prepare.html#broker-地址获取" target="_blank">Broker 地址获取</a>。

## 上报数据

在主菜单选择 `[1]` 进入 RID 子菜单，按需上报：

```
----- RID device access -----
 [1] Report capability set        (state,  device_type=7) [run first]
 [2] Report one RID  target now   (events, method=rid_infos)
 [3] Report one ADS-B target now  (events, method=adsb_infos)
 [4] Start periodic report (every 2s, demo RID/ADS-B targets)
 [5] Stop periodic report
 [b] Back
```

- `[1]` 上报能力集（首次进入请先执行）。
- `[2]` 上报一条 `rid_infos` 示例数据（无人机 Remote ID 探测结果）。
- `[3]` 上报一条 `adsb_infos` 示例数据（ADS-B 航空器探测结果）。
- `[4]` 启动周期上报：每 2 秒批量上报一次示例 RID / ADS-B 目标（推荐的上报模式，避免超过 5 Hz 频率限制）。
- `[5]` 停止周期上报。

各字段含义与完整协议详见 <a href="../function-set/rid-access.html" target="_blank">RID 功能</a>。
