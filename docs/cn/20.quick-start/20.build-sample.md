ESDK V2 提供了示例工程，演示第三方机库与 RID 设备如何接入 DJI 地面站、上报能力集并调用各功能接口。本章节介绍如何获取和编译示例工程。

SDK 发布包为自包含工程。解压后，可直接使用 CMake 编译；编译过程不依赖代码生成器、Python 或外部网络。

## 获取代码

可从 GitHub 克隆示例工程：

```bash
git clone https://github.com/dji-sdk/Edge-SDK-V2-Demo
```

若使用 SDK 发布包，请解压后进入 `edge-sdk-2.0.0/` 目录执行后续命令。

## 环境依赖

编译前请根据目标平台安装依赖：

| 场景 | 依赖 |
|:---|:---|
| host 编译（x86_64） | CMake（≥ 3.14）、C 编译器、libmosquitto、OpenSSL |
| aarch64 交叉编译 | CMake（≥ 3.14）、C 编译器、`gcc-aarch64-linux-gnu` |

Ubuntu / Debian 环境可执行以下命令安装依赖：

```bash
sudo apt install -y cmake build-essential libmosquitto-dev libssl-dev
sudo apt install -y gcc-aarch64-linux-gnu
```

`libuuid` 为可选依赖。安装 `uuid-dev` 后，`bid` / `tid` 使用标准 UUID；未安装时，SDK 会自动使用“设备 SN + 计数器”的方式生成。

## 填写凭据

`app_id`、`app_key`、`app_license` 的获取方式见 <a href="./dev-workflow.html#应用注册" target="_blank">开发流程总览 - 应用注册</a>。

开发者凭据支持以下两种配置方式：

1. **通过 CMake 变量传入（推荐）**：编译时传入 `DOCK_APP_ID`、`DOCK_APP_KEY`、`DOCK_APP_LICENSE` 等参数，CMake configure 阶段会根据 `config/dock_app_info.h.in` 自动生成 `dock_app_info.h`。

   ```bash
   cmake -B build \
     -DDOCK_APP_ID=xxx -DDOCK_APP_KEY=xxx -DDOCK_APP_LICENSE=xxx \
     -DDOCK_APP_NAME=xxx -DDOCK_DEVICE_SN=你的设备标识（device_id）
   ```

2. **手动修改模板文件**：编译前修改 `config/dock_app_info.h.in` 中的占位符配置，CMake configure 阶段会根据该模板生成 `dock_app_info.h`。

:::tip 说明：
协议中的 `device_id` 为设备唯一标识。示例工程默认使用设备 SN 作为 `device_id`，因此相关 CMake 变量命名为 `DOCK_DEVICE_SN` / `DOCK_RID_SN`。
:::

常用 CMake 变量如下：

| CMake 变量 | 说明 | 默认值 |
|:---|:---|:---|
| DOCK_APP_ID | 应用 ID | `your_app_id` |
| DOCK_APP_KEY | 应用密钥 | `your_app_key` |
| DOCK_APP_LICENSE | 应用 License | `your_app_license` |
| DOCK_APP_NAME | 应用名称 | `your_app_name` |
| DOCK_DEVICE_SN | 机库（dt5）设备标识（`device_id`） | `dock_sn_demo` |
| DOCK_RID_SN | RID（dt7）设备标识（`device_id`） | 留空时自动派生 |
| DOCK_BROKER_FALLBACK_IP | UDP 自动发现失败时使用的 Broker 回退地址 | `192.168.50.10` |
| DOCK_BROKER_PORT | Broker 端口 | `1883` |

:::warning 注意：
请勿将真实开发者凭据提交到代码仓库。
:::

### 配置 RID 设备标识

MQTT 账号 `"<app_id>_esdk_<device_id>"` 同时作为 MQTT `client_id` 与 Topic 中的设备标识。示例工程中，`DOCK_DEVICE_SN` / `DOCK_RID_SN` 会填入协议里的 `<device_id>`。若机库（dt5）与 RID 设备（dt7）使用同一个 `device_id`，后连接的设备会被拒绝，通常表现为 `CONNACK rc=5 (not authorised)`。

RID 设备标识的配置规则如下：

1. `DOCK_RID_SN` 为空，且同时编译机库与 RID 时，RID 设备 `device_id` 自动派生为 `<DOCK_DEVICE_SN>_rid`。
2. 需要使用独立 RID 设备标识时，可显式传入 `-DDOCK_RID_SN=你的RID设备标识`。
3. 只编译 RID（`-DEDGE_DOCK_ENABLE_DOCK=OFF`）时，`DOCK_DEVICE_SN` 会作为 RID 设备 `device_id` 使用，不追加 `_rid` 后缀。

configure 阶段会打印最终使用的设备标识，可根据以下日志确认配置是否符合预期：

```text
[edge-sdk] device SNs: dt5=... dt7=...
[edge-sdk] device SN: dt7=... (RID-only build)
```

### 运行期覆盖配置

如需将同一份编译产物切换到其他设备身份或 Broker，可使用环境变量覆盖编译期配置，无需重新编译：

```bash
DOCK_DEVICE_SN=xxx DOCK_RID_SN=yyy DOCK_BROKER_IP=192.168.50.10 DOCK_BROKER_PORT=1883 ./build/dock_cli
```

## 编译

工程支持两种编译方式，效果一致，任选其一。

### 方式一：使用 build.sh 脚本

脚本封装了常用参数。host 编译和交叉编译使用各自独立的输出目录，缓存互不影响：

```bash
./build.sh              # host 编译（x86_64），产物在 build/
./build.sh --cross      # aarch64 交叉编译，产物在 build-aarch64/
./build.sh -c           # 清除对应 build 目录后重新 configure
./build.sh -j 8         # 指定并发数
```

### 方式二：直接使用 CMake

```bash
cmake -B build && cmake --build build -j
```

发布包内包含 `sdk/` 快照，顶层 `CMakeLists.txt` 会自动使用静态快照编译，不执行代码生成流程。

## 编译产物

编译完成后，产物在 `build/`（host）或 `build-aarch64/`（交叉编译）目录下：

| 产物 | 说明 | 编译条件 |
|:---|:---|:---|
| dock_quickstart | 最小示例，用于验证设备接入链路 | `EDGE_DOCK_ENABLE_DOCK=ON` |
| dock_sample | 机库（dt5）单设备交互示例，用于调试机库功能 | `EDGE_DOCK_ENABLE_DOCK=ON` |
| rid_sample | RID（dt7）单设备交互示例，用于调试 RID / ADS-B 上报 | `EDGE_DOCK_ENABLE_RID=ON` |
| dock_cli | 全功能交互示例，先选择设备身份，再进入对应功能菜单 | `EDGE_DOCK_ENABLE_DOCK=ON` 且 `EDGE_DOCK_ENABLE_RID=ON` |

`dock_sample`、`rid_sample`、`dock_cli` 连接成功后会自动上报能力集，并等待能力集上报回执。运行方式详见 <a href="./run-sample.html" target="_blank">运行 Sample</a>。

## 只编译一种设备

若设备仅支持机库或 RID 中的一种，可关闭另一种设备的编译，以减小产物体积。被关闭设备对应的源码和协议代码均不会参与编译：

```bash
cmake -B build -DEDGE_DOCK_ENABLE_DOCK=ON  -DEDGE_DOCK_ENABLE_RID=OFF   # 只编译机库（dt5）
cmake -B build -DEDGE_DOCK_ENABLE_DOCK=OFF -DEDGE_DOCK_ENABLE_RID=ON    # 只编译 RID（dt7）
```

| 选项 | 对应设备 | 功能 | 对应示例 |
|:---|:---|:---|:---|
| EDGE_DOCK_ENABLE_DOCK | 机库（dt5） | 起降协同、开机与充电、机库配置 | `dock_quickstart`、`dock_sample` |
| EDGE_DOCK_ENABLE_RID | RID（dt7） | RID / ADS-B 监视上报 | `rid_sample` |

两个选项不可同时关闭。会话、发现、鉴权等公共能力始终参与编译。`dock_cli` 仅在两个选项均开启时生成。

## 交叉编译到 aarch64

执行以下命令交叉编译 aarch64 产物：

```bash
./build.sh --cross
file build-aarch64/dock_quickstart
```

`file` 命令输出应包含 `ELF ... ARM aarch64`。

交叉编译使用工程自带的 `third_party/aarch64-linux-gnu/` 目录中的头文件与 OpenSSL / libmosquitto 预编译库，并自动使用 `cmake/toolchain-aarch64.cmake` 工具链文件。编译前仅需安装 `gcc-aarch64-linux-gnu`。

部署到目标板时，可执行文件的 RPATH 为 `$ORIGIN/../lib`。请按以下目录结构放置可执行文件与依赖库：

```text
/opt/edge-sdk/
├── bin/dock_quickstart
└── lib/          # 拷贝 third_party/aarch64-linux-gnu/lib/*.so 到此目录
```

如需临时验证，也可通过 `LD_LIBRARY_PATH` 指定依赖库目录后运行：

```bash
LD_LIBRARY_PATH=<so目录> ./dock_quickstart
```

### 静态链接依赖库

若希望产物不依赖 `libssl`、`libcrypto`、`libmosquitto` 这三个动态库，可开启 `EDGE_SDK_STATIC_DEPS` 进行静态链接：

```bash
bash third_party/build-static-deps.sh aarch64-linux-gnu

cmake -B build-aarch64 -DEDGE_SDK_STATIC_DEPS=ON \
  -DCMAKE_TOOLCHAIN_FILE=cmake/toolchain-aarch64.cmake && cmake --build build-aarch64 -j

readelf -d build-aarch64/dock_quickstart | grep NEEDED
```

若静态链接成功，`readelf` 输出中不应包含 `libssl`、`libcrypto`、`libmosquitto`。glibc 仍为动态链接，不建议将 glibc 全静态链接。
