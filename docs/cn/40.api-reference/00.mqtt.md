ESDK V2 使用 MQTT 协议实现设备与 DJI 地面站之间的通信。设备通过 MQTT 长连接接入地面站 Broker 后，只需在连接时完成一次鉴权，即可持续进行数据上报与指令接收。本章节定义接入所需的登录信息拼接规则、Topic 列表与消息约束。

## 接入流程概览

设备从上电到正常通信的完整流程如下：

1. **获取认证凭证**：在 DJI 开发者平台注册应用，获取 app_id、app_key、app_license 三项认证信息，获取方式见 <a href="../quick-start/dev-workflow.html#应用注册" target="_blank">开发流程总览 - 应用注册</a>。
2. **建立 MQTT 连接**：拼接登录信息，连接 DJI 地面站 Broker（CONNACK=0 表示成功）。
3. **订阅 Topic**：根据业务需要订阅对应的下行 Topic（如 `state_reply`、`error` 等）。
4. **上报与通信**：通过发布 Topic 向地面站上报数据，具体消息格式见各功能的 API 说明。

## 登录信息

| 登录信息 | 拼接规则 | 示例 |
|---|---|---|
| Broker 地址 | 端口固定 1883。<ul><li>LAN 口（右侧网口）直连：固定为 <code>192.168.50.10:1883</code>（推荐）</li><li>WAN 口（左侧网口）经路由器：通过 UDP 广播自动发现（详见 <a href="../quick-start/environment-prepare.html#broker-地址获取" target="_blank">Broker 地址获取</a>），或通过行业应用确认</li></ul> | 192.168.50.10:1883 |
| username | `{app_id}_esdk_{设备序列号（device_id）}` | 123_esdk_MYDEV-01 |
| password | `{app_key}_{app_license}` | 84399396a48d_h50avVy... |
| ClientID | 与 username 相同 | 123_esdk_MYDEV-01 |

拼接示例：若 app_id=123、app_key=84399396a48d、app_license=h50a...、设备序列号（device_id）=MYDEV-01，则：

- username / ClientID：`123_esdk_MYDEV-01`
- password：`84399396a48d_h50a...`

:::tip 说明：
各 Topic 中的 `{client_id}` 即 MQTT ClientID，与 username 相同。例如 ClientID 为 `123_esdk_MYDEV-01` 时，状态上报 Topic 为 `thing/product/123_esdk_MYDEV-01/state`。
:::

:::warning 注意：
DJI 地面站会对认证信息进行校验，校验失败返回 CONNACK=5，仅 CONNACK=0 表示接入成功。
:::

## 连接参数

| 参数 | 建议值 | 说明 |
|---|---|---|
| Keep Alive | 30 秒 | 客户端与 Broker 之间的心跳间隔。 |
| Clean Session | true | 每次连接时创建新的会话，不保留离线消息。 |

### 重连策略

当连接断开或无法建立时，设备应采用指数退避 + 随机抖动策略进行重连，避免多台设备同时重连导致 Broker 瞬时负载过高。建议参数：

- 基础间隔：1 秒
- 最大间隔：60 秒
- 退避方式：每次失败后等待时间翻倍，并叠加 0~1 秒的随机抖动

## Topic 定义

### 订阅 Topic

设备连接成功后需订阅以下 Topic 以接收地面站的下行消息：

| Topic | QoS | 说明 | 备注 |
|---|:---:|---|---|
| thing/product/{client_id}/state_reply | 1 | 状态上报回复 | 必须订阅 |
| thing/product/{client_id}/error | 1 | 错误通知 | 建议始终订阅 |
| thing/product/{client_id}/events_reply | 1 | 事件上报回复 | 按需订阅 |
| thing/product/{client_id}/services | 1 | 设备服务下发 | 按需订阅 |
| thing/product/{client_id}/requests_reply | 1 | 请求上报回复 | 按需订阅 |

### 发布 Topic

设备通过以下 Topic 向地面站上报数据：

| Topic | QoS | 说明 | 备注 |
|---|:---:|---|---|
| thing/product/{client_id}/state | 1 | 状态上报 | 必须使用 |
| thing/product/{client_id}/events | 1 | 事件上报 | 按需使用 |
| thing/product/{client_id}/osd | 0 | 物模型推送 | 按需使用 |
| thing/product/{client_id}/services_reply | 1 | 设备服务回复 | 按需使用 |
| thing/product/{client_id}/requests | 1 | 请求上报 | 按需使用 |

## 消息约束

以下限制为单设备维度，即每台设备独立计算：

| 项目 | 限制 | 说明 |
|---|---|---|
| 消息频率 | 5 Hz | 单设备每秒最多发布 5 条消息（所有 Topic 合计） |
| 单条消息负载 | 2048 字节 | 单条 PUBLISH 的 payload 上限 |

超出限制时，DJI 地面站将拦截该消息并通过 error Topic 通知设备。

:::tip 说明：
部分设备需解除负载限制（如 RID 设备单条上报可达 20 KB），可通过设备类型声明解除，详见 <a href="./rid.html#负载扩展" target="_blank">RID 数据上报 - 负载扩展</a>。
:::
