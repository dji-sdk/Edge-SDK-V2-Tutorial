ESDK V2 uses the MQTT protocol to implement communication between devices and the DJI Ground Station. After a device connects to the Ground Station Broker via a persistent MQTT connection, it only needs to complete authentication once at connection time to continuously report data and receive commands. This section defines the login information concatenation rules, Topic list, and message constraints required for access.

## Access Workflow Overview

The complete workflow from device power-on to normal communication is as follows:

1. **Obtain authentication credentials**: Register an application on the DJI Developer Platform and obtain the three authentication credentials: app_id, app_key, and app_license. For how to obtain them, see <a href="../quick-start/dev-workflow.html#application-registration" target="_blank">Development Workflow Overview - Application Registration</a>.
2. **Establish MQTT connection**: Concatenate the login information and connect to the DJI Ground Station Broker (`CONNACK=0` indicates success).
3. **Subscribe to Topics**: Subscribe to the corresponding downlink Topics as needed (e.g., `state_reply`, `error`, etc.).
4. **Report and communicate**: Report data to the Ground Station by publishing to Topics. For the specific message formats, see the API reference of each feature.

## Login Information

| Login Information | Concatenation Rule | Example |
|---|---|---|
| Broker address | Port fixed at 1883.<ul><li>LAN port (right network port) direct connection: fixed at <code>192.168.50.10:1883</code> (recommended)</li><li>WAN port (left network port) via router: automatically discovered through UDP broadcast (see <a href="../quick-start/environment-prepare.html#obtaining-the-broker-address" target="_blank">Obtaining the Broker Address</a>), or confirmed via the enterprise application</li></ul> | 192.168.50.10:1883 |
| username | `{app_id}_esdk_{device_id}` | 123_esdk_MYDEV-01 |
| password | `{app_key}_{app_license}` | 84399396a48d_h50avVy... |
| ClientID | Same as username | 123_esdk_MYDEV-01 |

Here, `device_id` is the device's unique identifier. The ESDK V2 sample project uses the device SN as `device_id` by default.

Concatenation example: if `app_id=123`, `app_key=84399396a48d`, `app_license=h50a...`, `device_id=MYDEV-01`, then:

- username / ClientID: `123_esdk_MYDEV-01`
- password: `84399396a48d_h50a...`

:::tip Note:
The `{client_id}` in each Topic is the MQTT ClientID, which is the same as the username. For example, when the ClientID is `123_esdk_MYDEV-01`, the state reporting Topic is `thing/product/123_esdk_MYDEV-01/state`.
:::

:::warning Note:
The DJI Ground Station validates the authentication credentials. If validation fails, it returns `CONNACK=5`; only `CONNACK=0` indicates successful access.
:::

## Connection Parameters

| Parameter | Recommended Value | Description |
|---|---|---|
| Keep Alive | 30 seconds | Heartbeat interval between the client and the Broker. |
| Clean Session | true | Create a new session on each connection without retaining offline messages. |

### Reconnection Strategy

When the connection is disconnected or cannot be established, the device should use an exponential backoff + random jitter strategy for reconnection to avoid multiple devices reconnecting simultaneously and causing a momentary excessive load on the Broker. Recommended parameters:

- Base interval: 1 second
- Maximum interval: 30 seconds
- Backoff method: double the wait time after each failure, plus a random jitter of 0 to 1 second

## Topic Definitions

### Subscribe Topics

After connecting successfully, the device needs to subscribe to the following Topics to receive downlink messages from the Ground Station:

| Topic | QoS | Description | Remarks |
|---|:---:|---|---|
| thing/product/{client_id}/state_reply | 1 | State reporting reply | Required |
| thing/product/{client_id}/error | 1 | Error notification | Recommended to always subscribe |
| thing/product/{client_id}/events_reply | 1 | Event reporting reply | Subscribe as needed |
| thing/product/{client_id}/services | 1 | Device service delivery | Subscribe as needed |
| thing/product/{client_id}/requests_reply | 1 | Request reporting reply | Subscribe as needed |

### Publish Topics

The device reports data to the Ground Station via the following Topics:

| Topic | QoS | Description | Remarks |
|---|:---:|---|---|
| thing/product/{client_id}/state | 1 | State reporting | Required |
| thing/product/{client_id}/events | 1 | Event reporting | Use as needed |
| thing/product/{client_id}/osd | 0 | Thing model push | Use as needed |
| thing/product/{client_id}/services_reply | 1 | Device service reply | Use as needed |
| thing/product/{client_id}/requests | 1 | Request reporting | Use as needed |

## Message Constraints

The following limits are per-device, i.e., calculated independently for each device:

| Item | Limit | Description |
|---|---|---|
| Message frequency | 5 Hz | A single device can publish at most 5 messages per second (across all Topics combined) |
| Single message payload | 2048 bytes | The payload upper limit of a single PUBLISH |

When the limit is exceeded, the DJI Ground Station intercepts the message and notifies the device via the error Topic.

:::tip Note:
Only RID devices need to lift the payload limit (a single report can reach up to 20 KB); other devices such as docks do not need to lift it. RID devices lift it by appending the `@rid` suffix to the end of the MQTT username. See <a href="./rid.html#payload-extension" target="_blank">RID device - Payload Extension</a>.
:::
