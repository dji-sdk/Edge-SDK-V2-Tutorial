ESDK V2 uses the MQTT protocol for communication between devices and the DJI Ground Station. After connecting to the Ground Station Broker via a persistent MQTT connection, devices only need to authenticate once at connection time, and can then continuously report data and receive commands. This section defines the login information concatenation rules, Topic list, and message constraints required for access.

## Access Workflow Overview

The complete workflow from device power-on to normal communication is as follows:

1. **Obtain credentials**: Register an application on the DJI Developer Platform to get app_id, app_key, and app_license. For instructions, see <a href="../quick-start/dev-workflow.html#application-registration" target="_blank">Development Workflow - Application Registration</a>.
2. **Establish MQTT connection**: Concatenate login information and connect to the DJI Ground Station Broker (CONNACK=0 indicates success).
3. **Subscribe to Topics**: Subscribe to the required downstream Topics based on your use case (e.g., `state_reply`, `error`).
4. **Report and communicate**: Publish data to the Ground Station via the appropriate Topics. See the API documentation for each feature for specific message formats.

## Login Information

| Login Information | Concatenation Rule | Example |
|---|---|---|
| Broker Address | Port is fixed at 1883.<ul><li>LAN port (right network port) direct connection: fixed at <code>192.168.50.10:1883</code> (recommended)</li><li>WAN port (left network port) via router: automatically discovered via UDP broadcast (see <a href="../quick-start/environment-prepare.html#broker-address-retrieval" target="_blank">Broker Address Retrieval</a>), or confirmed through DJI Pilot 2 Enterprise</li></ul> | 192.168.50.10:1883 |
| username | `{app_id}_esdk_{device_id}` | 123_esdk_MYDEV-01 |
| password | `{app_key}_{app_license}` | 84399396a48d_h50avVy... |
| ClientID | Same as username | 123_esdk_MYDEV-01 |

Concatenation example: If app_id=123, app_key=84399396a48d, app_license=h50a..., and device_id=MYDEV-01, then:

- username / ClientID: `123_esdk_MYDEV-01`
- password: `84399396a48d_h50a...`

:::tip Note:
The `{client_id}` in each Topic is the MQTT ClientID, which is the same as the username. For example, when the ClientID is `123_esdk_MYDEV-01`, the state reporting Topic is `thing/product/123_esdk_MYDEV-01/state`.
:::

:::warning Note:
The DJI Ground Station validates the authentication information. Validation failure returns CONNACK=5; only CONNACK=0 indicates successful access.
:::

## Connection Parameters

| Parameter | Recommended Value | Description |
|---|---|---|
| Keep Alive | 30 seconds | The heartbeat interval between the client and the Broker. |
| Clean Session | true | Creates a new session on each connection without retaining offline messages. |

### Reconnection Strategy

When a connection is lost or cannot be established, devices should use an exponential backoff with random jitter strategy for reconnection, to avoid multiple devices reconnecting simultaneously and causing a sudden spike in Broker load. Recommended parameters:

- Base interval: 1 second
- Maximum interval: 60 seconds
- Backoff method: Double the wait time after each failure, plus a random jitter of 0–1 seconds

## Topic Definitions

### Subscribe Topics

After a successful connection, devices should subscribe to the following Topics to receive downstream messages from the Ground Station:

| Topic | QoS | Description | Remarks |
|---|:---:|---|---|
| thing/product/{client_id}/state_reply | 1 | State reporting reply | Required |
| thing/product/{client_id}/error | 1 | Error notification | Recommended to always subscribe |
| thing/product/{client_id}/events_reply | 1 | Event reporting reply | Subscribe as needed |
| thing/product/{client_id}/services | 1 | Device service commands | Subscribe as needed |
| thing/product/{client_id}/requests_reply | 1 | Request reporting reply | Subscribe as needed |

### Publish Topics

Devices report data to the Ground Station via the following Topics:

| Topic | QoS | Description | Remarks |
|---|:---:|---|---|
| thing/product/{client_id}/state | 1 | State reporting | Required |
| thing/product/{client_id}/events | 1 | Event reporting | Use as needed |
| thing/product/{client_id}/osd | 0 | Thing model push | Use as needed |
| thing/product/{client_id}/services_reply | 1 | Device service reply | Use as needed |
| thing/product/{client_id}/requests | 1 | Request reporting | Use as needed |

## Message Constraints

The following limits are per-device, calculated independently for each device:

| Item | Limit | Description |
|---|---|---|
| Message Rate | 5 Hz | Maximum 5 messages published per second per device (across all Topics) |
| Single Message Payload | 2048 bytes | Maximum payload size per single PUBLISH message |

When the limit is exceeded, the DJI Ground Station will block the message and notify the device via the error Topic.

:::tip Note:
Some devices need to lift the payload limit (e.g., RID devices where a single report can reach 20 KB). This can be done through device type declaration. For details, see <a href="./rid.html#payload-extension" target="_blank">RID Data Reporting - Payload Extension</a>.
:::
