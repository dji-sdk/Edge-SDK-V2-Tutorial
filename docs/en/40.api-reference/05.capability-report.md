After a device completes MQTT access and authentication, it must first report its capability set once to declare the device type and supported capabilities, based on which the DJI Ground Station identifies the device. This section defines the common protocol for capability set reporting, which both RID and third-party dock follow; only the specific content of `device_type` and `capabilities` differs.

`device_type` determines the device's access identity, with the following values:

- `device_type = 5`: Third-party dock, see <a href="./dock/charging.html" target="_blank">Third-Party Dock Device</a>
- `device_type = 7`: RID, see <a href="./rid.html" target="_blank">RID device</a>

:::warning Note:
A single device can only declare one `device_type` and cannot connect as multiple identities simultaneously.
:::

## Topic

- **Report**: `thing/product/{client_id}/state`, direction: Device → DJI Ground Station, QoS 1
- **Reply**: `thing/product/{client_id}/state_reply`, direction: DJI Ground Station → Device, QoS 1

## Common Fields

<div class="collapsible" />

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| bid | string | Yes | Business ID, non-empty |
| tid | string | Yes | Transaction tracking ID, non-empty |
| timestamp | integer | Yes | Millisecond timestamp, ≥ 0 |
| version | string | Yes | Protocol version, fixed at 1.0.0 |
| data | object | Yes | Message data body |
| >>device_type | integer | Yes | Device type.<ul><li>5: Third-party dock</li><li>7: RID device</li></ul> |
| >>capabilities | object | Yes | Capability set. The specific fields vary by device type; see the capability set descriptions for each device below. |

## Capability Set of Third-Party Dock

When `device_type = 5`, `capabilities` currently only needs to report an empty object `{}`.

```json
{
  "bid": "UUID-CAPS-XXXX-XXXX",
  "tid": "UUID-TRACK-YYYY-YYYY",
  "data": {
    "device_type": 5,
    "capabilities": {}
  },
  "version": "1.0.0",
  "timestamp": 1757400927326
}
```

## Capability Set of RID Device

When `device_type = 7`, `capabilities` is used to declare whether RID and ADS-B capabilities are supported.

```json
{
  "bid": "UUID-CAPS-XXXX-XXXX",
  "data": {
    "device_type": 7,
    "capabilities": {
      "rid": {
        "supported": true,
        "version": "1.0.0"
      },
      "adsb": {
        "supported": true,
        "version": "1.0.0"
      }
    }
  },
  "tid": "UUID-TRACK-YYYY-YYYY",
  "timestamp": 1757400927326,
  "version": "1.0.0"
}
```

<div class="collapsible" />

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| capabilities | object | Yes | Capability set. An empty object `{}` is allowed. |
| >>rid | object | No | RID capability declaration. |
| >>>>supported | boolean | No | Whether RID is supported. |
| >>>>version | string | No | RID capability version, e.g., 1.0.0. |
| >>adsb | object | No | ADS-B capability declaration. |
| >>>>supported | boolean | No | Whether ADS-B is supported. |
| >>>>version | string | No | ADS-B capability version, e.g., 1.0.0. |

## Reporting Result

```json
{
  "bid": "UUID-CAPS-XXXX-XXXX",
  "tid": "UUID-TRACK-YYYY-YYYY",
  "data": { "result": 0 },
  "version": "1.0.0",
  "timestamp": 1757400927326
}
```

| Field | Type | Description |
|:---|:---|:---|
| result | integer | Processing result. 0 indicates success; other values indicate failure. |

:::warning Note:
The capability set takes effect only when result = 0, after which messages of each capability domain can be delivered/reported.
:::
