This section defines the interfaces involved in RID device access to ESDK V2, including Payload Extension, Capability Set Reporting, RID Information Reporting, and ADS-B Information Reporting payload structures and field descriptions.

## Payload Extension

A single RID device events report can reach approximately 20 KB, exceeding the DJI Ground Station's default payload limit of 2048 bytes. When connecting, the `@rid` suffix must be appended to the end of the MQTT username to lift the limit. Additionally, the `device_type` in the capability set report must be 7, consistent with the username declaration.

| Login Information | Concatenation Rule |
|:---|:---|
| username | `{app_id}_esdk_{device_id}@rid` |
| password | Same as standard access, no modification needed |

:::warning Note:
For the complete login information concatenation rules, see <a href="./mqtt.html#login-information" target="_blank">Access and Authentication - Login Information</a>. RID devices only append `@rid` to the end of the username; everything else remains unchanged.
:::

## Common Fields

The following fields are common top-level fields for all reporting messages and are not repeated in individual interface field descriptions.

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| bid | string | Yes | Business ID, non-empty. |
| tid | string | Yes | Transaction tracking ID, non-empty. |
| timestamp | integer | Yes | Millisecond timestamp, >= 0. |
| version | string | Yes | Protocol version, fixed at `1.0.0`. |
| method | string | No | Method identifier. Required for events reporting: `rid_infos` for RID reporting, `adsb_infos` for ADS-B reporting; not present in state reporting. |
| data | object | Yes | Message data body. |

## Capability Set Reporting

### Topic

- **Topic**: `thing/product/{client_id}/state`
- **Direction**: Device -> DJI Ground Station
- **QoS**: 1

### Payload Example

```json
{
  "bid": "UUID-CAPS-XXXX-XXXX",
  "data": {
    "device_type": 7,
    "capabilities": {
      "rid": {
        "supported": true,
        "version": "1.0.0"
      },
      "adsb": {
        "supported": true,
        "version": "1.0.0"
      }
    }
  },
  "tid": "UUID-TRACK-YYYY-YYYY",
  "timestamp": 1757400927326,
  "version": "1.0.0"
}
```

### Field Description

For common fields at the top level of the message, see [Common Fields](#common-fields). The following are fields within data:

<div class="collapsible" />

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| device_type | integer | Yes | Device type. Fixed at 7 for RID devices. |
| capabilities | object | Yes | Capability set. An empty object `{}` is allowed. |
| >>rid | object | No | RID capability declaration. |
| >>>>supported | boolean | No | Whether RID is supported. |
| >>>>version | string | No | RID capability version, e.g., `1.0.0`. |
| >>adsb | object | No | ADS-B capability declaration. |
| >>>>supported | boolean | No | Whether ADS-B is supported. |
| >>>>version | string | No | ADS-B capability version, e.g., `1.0.0`. |

### Reporting Result

After subscribing to state_reply, the DJI Ground Station will reply after the capability set is reported:

- **Topic**: `thing/product/{client_id}/state_reply`
- **Direction**: DJI Ground Station -> Device
- **QoS**: 1

```json
{
  "bid": "UUID-CAPS-XXXX-XXXX",
  "data": {
    "result": 0
  },
  "tid": "UUID-TRACK-YYYY-YYYY",
  "timestamp": 1757400927326
}
```

| Field | Type | Description |
|:---|:---|:---|
| result | integer | Processing result. 0 indicates success; other values indicate failure. |

:::warning Note:
Only when result = 0 does it indicate successful access, and RID / ADS-B event reporting can begin.
:::

## RID Information Reporting

### Topic

- **Topic**: `thing/product/{client_id}/events`
- **Direction**: Device -> DJI Ground Station
- **QoS**: 1
- **method**: `rid_infos`

### Payload Example

```json
{
  "tid": "UUID-TRACK-YYYY-YYYY",
  "bid": "UUID-CAPS-XXXX-XXXX",
  "timestamp": 1757400927326,
  "method": "rid_infos",
  "version": "1.0.0",
  "data": {
    "capacity_percent": 48,
    "power_supply": 0,
    "gnss": {
      "engine": 0,
      "flag": 2,
      "time": "20250723-142355",
      "lat": 22.58821,
      "lon": 113.50389,
      "alt": 503,
      "satellite": 5,
      "hdop": 5
    },
    "rid": [
      {
        "osid": "1581F6N8C243L0039TB9",
        "rssi": -79,
        "fre": 1,
        "uatype": 2,
        "status": 0,
        "heading": 12,
        "speed": 5.4,
        "uprate": 1.5,
        "lon": 113.22128,
        "lat": 22.58079,
        "altgeo": 120,
        "altbaro": 120,
        "height": 50,
        "op_lon": 113.22322,
        "op_lat": 22.58475,
        "op_alt": 20,
        "uatime": 174462011
      }
    ]
  }
}
```

### Field Description

For common fields at the top level of the message, see [Common Fields](#common-fields). The following are fields within data:

<div class="collapsible" />

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| capacity_percent | integer | No | Remaining battery percentage of the reporting device, value range [0, 100]. |
| power_supply | integer | No | Power supply type identifier. The current protocol does not define specific value meanings. Contact DJI Technical Support if needed. |
| gnss | object | No | Positioning information of the reporting device itself. |
| >>engine | integer | No | Positioning engine.<ul><li>0: Hybrid positioning</li><li>1: GPS system</li><li>2: BeiDou system</li></ul> |
| >>flag | integer | No | Positioning flag.<ul><li>0: Not positioned</li><li>1: SPS mode</li><li>2: Differential mode</li><li>3: PPS mode</li></ul> |
| >>time | string | No | UTC time, format: YYYYMMDD-HHMMSS (e.g., `20250723-142355`). |
| >>lat | number | No | Latitude. |
| >>lon | number | No | Longitude. |
| >>alt | number | No | Altitude. |
| >>satellite | integer | No | Number of positioning satellites. |
| >>hdop | number | No | Horizontal Dilution of Precision. |
| rid | array&lt;object&gt; | No | List of drone Remote ID targets detected in this report. |
| >>osid | string | No | Drone ID. |
| >>rssi | number | No | Signal strength. Higher values indicate stronger signal. |
| >>fre | integer | No | Communication channel.<ul><li>0: WIFI 5.8G</li><li>1: WIFI 2.4G</li><li>2: Bluetooth</li></ul> |
| >>uatype | integer | No | UA (Unmanned Aircraft) type.<ul><li>0: Unknown/other</li><li>1: Fixed-wing aircraft</li><li>2: Drone/multi-rotor</li><li>3: Helicopter/rotorcraft</li><li>4: VTOL Fixed-Wing</li><li>5: Paraglider/paramotor</li><li>6: Glider</li><li>7: Kite</li><li>8: Balloon</li><li>9: Captive balloon</li><li>10: Airship</li><li>11: Parachute (unpowered)</li><li>12: Rocket</li><li>13: Tethered powered aircraft</li><li>14: Ground obstacle</li><li>15: Other</li></ul> |
| >>status | integer | No | Flight status.<ul><li>0: Unknown</li><li>1: Ground</li><li>2: Airborne</li><li>3: Emergency</li></ul> |
| >>heading | number | No | Track angle. 361 indicates unknown or hovering status. |
| >>speed | number | No | Horizontal speed of the drone, in m/s. |
| >>uprate | number | No | Vertical speed of the drone, in m/s. |
| >>lon | number | No | Longitude of the drone. |
| >>lat | number | No | Latitude of the drone. |
| >>altgeo | number | No | Geodetic altitude of the drone. -1000 indicates unknown. |
| >>altbaro | number | No | Barometric altitude of the drone. -1000 indicates unknown. |
| >>height | number | No | Height above ground of the drone. -1000 indicates unknown. |
| >>op_lon | number | No | Operator position longitude. |
| >>op_lat | number | No | Operator position latitude. |
| >>op_alt | number | No | Operator position altitude, in meters. |
| >>uatime | number | No | Internal time of the drone. |

:::warning Note:
gnss describes the position of the reporting device itself; lat / lon / op_lat / op_lon in rid[] describe the positions of the detected drone and its operator. These must not be confused.
:::

## ADS-B Information Reporting

### Topic

- **Topic**: `thing/product/{client_id}/events`
- **Direction**: Device -> DJI Ground Station
- **QoS**: 1
- **method**: `adsb_infos`

### Payload Example

```json
{
  "tid": "4fad3f06-a84e-476a-ba31-1ba330fd5865",
  "bid": "602c4276-f28f-42f9-ab30-4a85072140f5",
  "timestamp": 1777348300100,
  "method": "adsb_infos",
  "version": "1.0.0",
  "data": {
    "capacity_percent": 48,
    "power_supply": 0,
    "gnss": {
      "engine": 0,
      "flag": 2,
      "time": "20260428-035140",
      "lat": 22.793106,
      "lon": 114.358677,
      "alt": 40.9,
      "satellite": 12,
      "hdop": 5
    },
    "adsb": [
      {
        "icao": "781EB7",
        "callsign": "CSN1735",
        "height": 11003,
        "lat": 22.58821,
        "lon": 113.50389,
        "speed": 941,
        "heading": 185,
        "uprate": 0.32
      }
    ]
  }
}
```

### Field Description

For common fields at the top level of the message, see [Common Fields](#common-fields). The following are fields within data:

<div class="collapsible" />

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| capacity_percent | integer | No | Remaining battery percentage of the reporting device, value range [0, 100]. |
| power_supply | integer | No | Power supply type identifier. The current protocol does not define specific value meanings. Contact DJI Technical Support if needed. |
| gnss | object | No | Positioning information of the reporting device itself. |
| >>engine | integer | No | Positioning engine.<ul><li>0: Hybrid positioning</li><li>1: GPS system</li><li>2: BeiDou system</li></ul> |
| >>flag | integer | No | Positioning flag.<ul><li>0: Not positioned</li><li>1: SPS mode</li><li>2: Differential mode</li><li>3: PPS mode</li></ul> |
