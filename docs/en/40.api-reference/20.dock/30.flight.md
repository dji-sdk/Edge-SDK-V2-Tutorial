This section defines the MQTT interfaces for a third-party dock to work with the O4 Ground Station to complete drone takeoff, landing, and mission exception recovery. Unlike power-on and charging, Takeoff-Landing Coordination is a **downlink** process: the Ground Station issues commands via services, and the third-party dock responds (services_reply) and reports execution progress via events. For the overall operation timing (takeoff / landing / exception recovery process), see <a href="../../function-set/dock-access/flight.html" target="_blank">Function Set - Takeoff-Landing Coordination</a>.

:::tip Note:
After a third-party dock is connected, it must first complete Capability Set Reporting (`device_type = 5`). Only after result = 0 is returned can the following interactions be performed. For details, see <a href="../capability-report.html" target="_blank">Capability Set Reporting</a>.
:::

## Protocol Description

The Topics involved in the interfaces are as follows:

| Type | Direction | Topic |
|:---|:---|:---|
| Command issue | DJI Ground Station → Third-party dock | thing/product/{client_id}/services |
| Command reply | Third-party dock → DJI Ground Station | thing/product/{client_id}/services_reply |
| Progress reporting | Third-party dock → DJI Ground Station | thing/product/{client_id}/events |

The interfaces provided in this section are as follows:

| Stage | Command (services) | Event Reporting (events) |
|:---|:---|:---|
| Takeoff preparation | airport_takeoff_prepare | airport_takeoff_prepare |
| Takeoff end | airport_takeoff_end | airport_takeoff_end |
| Landing preparation | airport_landing_prepare | airport_landing_prepare |
| Landing end | airport_landing_end | airport_landing_end |
| Mission exception recovery | airport_abnormal_recovery | airport_abnormal_recovery |

:::tip Note:
The `method` for command issue and event reporting is the same; message types are distinguished by Topic (services / events). For `output.status` value descriptions, see the "Progress Reporting Field Description" subsection of each stage.
:::

## Common Fields

The following fields are common top-level fields for all messages and are not repeated in individual interface field descriptions.

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| bid | string | Yes | Business ID, non-empty. |
| tid | string | Yes | Transaction tracking ID, non-empty. |
| timestamp | integer | Yes | Millisecond timestamp, ≥ 0. |
| version | string | Yes | Protocol version, fixed at 1.0.0. |
| method | string | Yes | Method identifier. |
| data | object | Yes | Message data body. |
| gateway | string | No | Appears only in the command reply (services_reply). Its value is the serial number gateway_sn of the O4 Ground Station (gateway) that processed the request, filled in by the Ground Station to identify the reply source. |

## Takeoff Preparation

### Request Payload Example

- **Topic**: `thing/product/{client_id}/services`
- **Direction**: DJI Ground Station → Third-party dock
- **method**: `airport_takeoff_prepare`

```json
{
  "bid": "UUID-CAPS-XXXX-XXXX",
  "tid": "UUID-TRACK-YYYY-YYYY",
  "data": {},
  "method": "airport_takeoff_prepare",
  "version": "1.0.0",
  "timestamp": 1757400927326
}
```

### Request Field Description

For top-level fields, see <a href="#common-fields">Common Fields</a>. `data` is an empty object `{}` with no specific fields.

### Response Payload Example

- **Topic**: `thing/product/{client_id}/services_reply`
- **Direction**: Third-party dock → DJI Ground Station

```json
{
  "bid": "UUID-CAPS-XXXX-XXXX",
  "data": {
    "output": { "status": "in_progress" },
    "result": 0
  },
  "method": "airport_takeoff_prepare",
  "tid": "UUID-TRACK-YYYY-YYYY",
  "timestamp": 1773816352073,
  "version": "1.0.0",
  "gateway": "gateway_sn"
}
```

### Response Field Description

For top-level fields, see <a href="#common-fields">Common Fields</a>. The `data` fields are described below:

<div class="collapsible" />

| Field | Type | Description |
|:---|:---|:---|
| result | int | Reply result. Non-zero indicates an error. |
| output | object | Output. |
| >>status | string | Execution status.<ul><li>sent: Issued</li><li>in_progress: In progress</li><li>paused: Paused</li><li>ok: Success</li><li>failed: Failed</li><li>rejected: Rejected</li><li>canceled: Canceled</li><li>timeout: Timeout</li></ul> |

### Progress Reporting Payload Example

- **Topic**: `thing/product/{client_id}/events`
- **Direction**: Third-party dock → DJI Ground Station

```json
{
  "bid": "UUID-CAPS-XXXX-XXXX",
  "tid": "UUID-TRACK-YYYY-YYYY",
  "data": {
    "result": 0,
    "output": {
      "progress": { "percent": 45 },
      "status": "in_progress"
    }
  },
  "method": "airport_takeoff_prepare",
  "version": "1.0.0",
  "timestamp": 1757400927326
}
```

### Progress Reporting Field Description

For top-level fields, see <a href="#common-fields">Common Fields</a>. The `data` fields are described below:

|:---|:---|:---|
