This section defines the MQTT interfaces for a third-party dock to query and set the dock Thing Model (TSL) properties.

:::tip Note:
After a third-party dock is connected, it must first complete Capability Set Reporting (`device_type = 5`). Only after result = 0 is returned can the following Thing Model properties be read or written. For details, see <a href="../capability-report.html" target="_blank">Capability Set Reporting</a>.
:::

## Protocol Description

The Topics involved in the interfaces are as follows:

| Type | Direction | Topic |
|:---|:---|:---|
| Request | Third-party dock → DJI Ground Station | thing/product/{client_id}/requests |
| Reply | DJI Ground Station → Third-party dock | thing/product/{client_id}/requests_reply |

The interfaces provided in this section are as follows:

| Operation | method |
|:---|:---|
| Query Thing Model parameters | get_tsl_params |
| Set Thing Model parameters | set_tsl_params |

## Common Fields

The following fields are common top-level fields for all messages and are not repeated in individual interface field descriptions.

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| bid | string | Yes | Business ID, non-empty. |
| tid | string | Yes | Transaction tracking ID, non-empty. |
| timestamp | integer | Yes | Millisecond timestamp, ≥ 0. |
| version | string | Yes | Protocol version, fixed at 1.0.0. |
| method | string | Yes | Method identifier. |
| data | object | Yes | Message data body. |
| gateway | string | No | Appears only in the response (requests_reply). Its value is the serial number gateway_sn of the O4 Ground Station (gateway) that processed the request, filled in by the Ground Station to identify the response source. |

## Query Thing Model Parameters

### Request Payload Example

- **Topic**: `thing/product/{client_id}/requests`
- **Direction**: Third-party dock → DJI Ground Station
- **method**: `get_tsl_params`

```json
{
  "bid": "UUID-CAPS-XXXX-XXXX",
  "tid": "UUID-TRACK-YYYY-YYYY",
  "data": {
    "params": ["drone_home_point_longitude", "drone_home_point_latitude"]
  },
  "method": "get_tsl_params",
  "version": "1.0.0",
  "timestamp": 1757400927326
}
```

### Request Field Description

For top-level fields, see <a href="#common-fields">Common Fields</a>. The `data` fields are described below:

| Field | Type | Description |
|:---|:---|:---|
| params | array | Array of property names to obtain. For property names, see <a href="#thing-model-parameter-table">Thing Model Parameter Table</a>. |

### Response Payload Example

- **Topic**: `thing/product/{client_id}/requests_reply`
- **Direction**: DJI Ground Station → Third-party dock

```json
{
  "bid": "UUID-CAPS-XXXX-XXXX",
  "tid": "UUID-TRACK-YYYY-YYYY",
  "data": {
    "result": 0,
    "output": {
      "drone_home_point_longitude": 113.95,
      "drone_home_point_latitude": 22.58
    }
  },
  "method": "get_tsl_params",
  "timestamp": 1757400927326,
  "gateway": "gateway_sn"
}
```

### Response Field Description

For top-level fields, see <a href="#common-fields">Common Fields</a>. The `data` fields are described below:

| Field | Type | Description |
|:---|:---|:---|
| result | int | Request result. Non-zero indicates an error. |
| error_reason | string | When result is non-zero, outputs the corresponding error message to prompt the user. |
| output | object | The set of parameters successfully obtained. Missing parameters indicate that those parameters failed to be obtained. For fields, see <a href="#thing-model-parameter-table">Thing Model Parameter Table</a>. |

## Set Thing Model Parameters

### Request Payload Example

- **Topic**: `thing/product/{client_id}/requests`
- **Direction**: Third-party dock → DJI Ground Station
- **method**: `set_tsl_params`

```json
{
  "bid": "UUID-CAPS-XXXX-XXXX",
  "tid": "UUID-TRACK-YYYY-YYYY",
  "data": {
    "params": [
      { "drone_home_point_longitude": 113.95 },
      { "drone_home_point_latitude": 22.58 },
      { "station_work_mode": 1 }
    ]
  },
  "method": "set_tsl_params",
  "version": "1.0.0",
  "timestamp": 1757400927326
}
```

### Request Field Description

For top-level fields, see <a href="#common-fields">Common Fields</a>. The `data` fields are described below:

| Field | Type | Description |
|:---|:---|:---|
| params | array | Array of property changes. Each element is a single-key object `{property name: value}`. |

### Response Payload Example

- **Topic**: `thing/product/{client_id}/requests_reply`
- **Direction**: DJI Ground Station → Third-party dock

```json
{
  "bid": "UUID-CAPS-XXXX-XXXX",
  "tid": "UUID-TRACK-YYYY-YYYY",
  "data": {
    "result": 0,
    "output": {
      "drone_home_point_longitude": 113.95,
      "drone_home_point_latitude": 22.58,
      "station_work_mode": 1
    }
  },
  "method": "set_tsl_params",
  "timestamp": 1757400927326,
  "gateway": "gateway_sn"
}
```

### Response Field Description

For top-level fields, see <a href="#common-fields">Common Fields</a>. The `data` fields are described below:

<div class="collapsible" />

| Field | Type | Description |
|:---|:---|:---|
| result | int | Request result. Non-zero indicates an error. |
| error_reason | string | When result is non-zero, outputs the corresponding error message to prompt the user. |
| output | object | The set of parameters successfully set. Missing parameters indicate that those parameters failed to be set. |

| air_to_conditionner_current | ACDC output current to air conditioner power supply, unit: mA. | — | read_only |
| acdc_temperature | ACDC temperature, unit: 0.1℃. | — | read_only |

:::tip Note:
- When setting or reading parameters, values must be passed according to the data type in the "Type" column of the table above. A type mismatch will cause the parameter get/set to fail. Among them, `double` type fields such as longitude, latitude, and height must not be passed as integers; otherwise the decimal part will be truncated, resulting in incorrect position data.
- Parameters whose Type column is `—` are all read-only reported parameters (`read_only`). Their values are pushed by the gateway via OSD; developers only need to read them, without setting a type.
:::

## charger_state Value Description

<div class="collapsible" />

| Value | Meaning |
|:---|:---|
| 0 | Not charging |
| 1 | Waiting for charging command |
| 2 | Charging |
| 3 | Charging complete |
| 4 | Unable to establish communication with the drone |
| 5 | Input voltage or battery voltage cannot meet the charging start condition |
| 6 | Excessive voltage difference on the interface board during charging |
| 7 | No charging current during charging |
| 8 | Recoverable battery abnormality (usually a temperature abnormality) |
| 9 | Unrecoverable battery abnormality (usually a temperature abnormality) |
| 10 | Excessive voltage difference between the two batteries, and the drone is powered on |
| 11 | Battery temperature is higher than the charging start temperature |
| 12 | Battery not in position |
| 13 | Power supply abnormality |
| 14 | Battery heating |
