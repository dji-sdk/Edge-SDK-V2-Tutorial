This section defines the MQTT interfaces for a third-party dock to power on/off and start/stop charging the drone inside the dock. For the complete charging process (including prerequisite configuration), see <a href="../../function-set/dock-access/charging.html" target="_blank">Function Set - Power-On and Charging</a>.

:::tip Note:
- The power-on and charging capability interfaces of ESDK V2 must be used together with the DJI wireless charging module. The wireless charging module is provided by DJI. To obtain it, email [dev@dji.com](mailto:dev@dji.com) to contact the SDK technical support team.
- After a third-party dock is connected, it must first complete Capability Set Reporting (`device_type = 5`). Only after result = 0 is returned can the following commands be issued. For details, see <a href="../capability-report.html" target="_blank">Capability Set Reporting</a>.
:::

## Protocol Description

The Topics involved in the interfaces are as follows:

| Type | Direction | Topic |
|:---|:---|:---|
| Request | Third-party dock → DJI Ground Station | thing/product/{client_id}/requests |
| Reply | DJI Ground Station → Third-party dock | thing/product/{client_id}/requests_reply |

The interfaces provided in this section are as follows:

| Operation | method |
|:---|:---|
| Power on drone | drone_open |
| Power off drone | drone_close |
| Start charging | charge_open |
| Stop charging | charge_close |

## Common Fields

The following fields are common top-level fields for all messages and are not repeated in individual interface field descriptions.

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| bid | string | Yes | Business ID, non-empty. |
| tid | string | Yes | Transaction tracking ID, non-empty. |
| timestamp | integer | Yes | Millisecond timestamp, ≥ 0. |
| version | string | Yes | Protocol version, fixed at 1.0.0. |
| method | string | Yes | Method identifier. |
| data | object | Yes | Message data body. |
| gateway | string | No | Appears only in the response (requests_reply). Its value is the serial number gateway_sn of the O4 Ground Station (gateway) that processed the request, filled in by the Ground Station to identify the response source. |

## Power On Drone

### Request Payload Example

- **Topic**: `thing/product/{client_id}/requests`
- **Direction**: Third-party dock → DJI Ground Station
- **method**: `drone_open`

```json
{
  "bid": "UUID-CAPS-XXXX-XXXX",
  "tid": "UUID-TRACK-YYYY-YYYY",
  "data": {},
  "method": "drone_open",
  "version": "1.0.0",
  "timestamp": 1757400927326
}
```

### Request Field Description

For top-level fields, see <a href="#common-fields">Common Fields</a>. `data` is an empty object `{}` with no specific fields.

### Response Payload Example

- **Topic**: `thing/product/{client_id}/requests_reply`
- **Direction**: DJI Ground Station → Third-party dock

```json
{
  "bid": "UUID-CAPS-XXXX-XXXX",
  "data": {
    "output": { "status": "in_progress" },
    "result": 0
  },
  "method": "drone_open",
  "tid": "UUID-TRACK-YYYY-YYYY",
  "timestamp": 1773816352073,
  "version": "1.0.0",
  "gateway": "gateway_sn"
}
```

### Response Field Description

For top-level fields, see <a href="#common-fields">Common Fields</a>. The `data` fields are described below:

<div class="collapsible" />

| Field | Type | Description |
|:---|:---|:---|
| result | int | Request result. Non-zero indicates an error. |
| output | object | Output. |
| >>status | string | Execution status.<ul><li>sent: Issued</li><li>in_progress: In progress</li><li>paused: Paused</li><li>ok: Success</li><li>failed: Failed</li><li>rejected: Rejected</li><li>canceled: Canceled</li><li>timeout: Timeout</li></ul> |
