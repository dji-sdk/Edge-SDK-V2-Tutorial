This section summarizes the frequently asked questions and their solutions when a device accesses the DJI Ground Station via MQTT.

  <thead>
    <tr>
      <th style="text-align: center;">No.</th>
      <th>Symptom</th>
      <th>Cause</th>
      <th>Solution</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td style="text-align: center;">1</td>
      <td>Connection returns CONNACK=5</td>
      <td>Validation of app_id, app_key, or app_license failed, or the concatenation format of the username/password is incorrect</td>
      <td>Verify the authentication information. The username format is <code>{app_id}_esdk_{device_id}</code>, and the password format is <code>{app_key}_{app_license}</code>. See <a href="./api-reference/mqtt.html#login-information" target="_blank">Access and Authentication - Login Information</a>.</td>
    </tr>
    <tr>
      <td style="text-align: center;">2</td>
      <td>Connection does not respond for a long time / cannot connect</td>
      <td>Not connected to the correct Broker, or the device and the O4 Ground Station are not in the same subnet</td>
      <td>Confirm the Broker IP (see <a href="./quick-start/environment-prepare.html#obtaining-the-broker-address" target="_blank">Obtaining the Broker Address</a>); check the IP subnet and port 1883.</td>
    </tr>
    <tr>
      <td style="text-align: center;">3</td>
      <td>state_reply returns a non-zero result</td>
      <td>The capability set payload is invalid, or a required field such as device_type is incorrect</td>
      <td>Verify the required fields of the capability set payload; device_type must match the device type. See <a href="./api-reference/capability-report.html" target="_blank">Capability Set Reporting</a>.</td>
    </tr>
    <tr>
      <td style="text-align: center;">4</td>
      <td>An error interception notification is received after reporting an event</td>
      <td>1. The reporting frequency exceeds 5 Hz, or a single payload exceeds 2048 bytes;<br/>2. The message format is incorrect, such as misspelled field names or incorrect field types.</td>
      <td>1. Reduce the reporting frequency (it is recommended to merge and cache messages before reporting them in batches); when a single payload of an RID device is large, the limit can be removed by appending the <code>@rid</code> suffix to the end of the username (see <a href="./api-reference/rid.html#payload-extension" target="_blank">Payload Extension</a>).<br/>2. Verify that the payload is valid JSON, and that the field names' spelling and field types are consistent with the protocol definitions.</td>
    </tr>
  </tbody>
</table>
