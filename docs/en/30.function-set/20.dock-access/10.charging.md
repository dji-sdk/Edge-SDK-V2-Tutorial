ESDK V2 enables a third-party dock to **power on / power off the drone and start / stop charging** for the drone inside the dock, providing four operations in total.

:::tip Note:
- The power-on and charging capability interfaces of ESDK V2 must be used together with the DJI wireless charging module. The wireless charging module is provided by DJI. To obtain it, email [dev@dji.com](mailto:dev@dji.com) to contact the SDK technical support team.
- The "power on" referred to in this capability is the power on/off of the **drone**, not the operation of the dock cover.
:::

## Feature Description

Power-on and charging include four operations. All are actively initiated by the third-party dock to the DJI Ground Station. After processing, the Ground Station returns the current status, following a request/reply interaction model:

| Operation | Description | Command (method) |
|:---|:---|:---|
| Drone power on | Power on the drone inside the dock | drone_open |
| Drone power off | Power off the drone inside the dock | drone_close |
| Start charging | Start charging the drone battery | charge_open |
| Stop charging | Stop charging the drone battery | charge_close |

Arrange the command order reasonably (e.g., power on before charging), and confirm that the `result` of the previous command's reply is 0 before proceeding to the next step.

## Access Workflow

This capability belongs to the third-party dock capability domain. The access steps are as follows:

1. **MQTT access and authentication**: Assemble the login information and connect to the DJI Ground Station Broker. See <a href="../../api-reference/mqtt.html" target="_blank">Access and Authentication</a> for details.
2. **Capability Set Reporting**: Report the device type (`device_type = 5`) and capability declaration through the state Topic. Commands can only be issued after receiving result = 0. See <a href="../../api-reference/capability-report.html" target="_blank">Capability Set Reporting</a> for details.
3. **Issue power-on / charging commands**: Publish the corresponding command to the requests Topic and obtain the result from requests_reply.

## Full Operation Sequence (Including Prerequisite Configuration)

The following diagram shows the complete end-to-end sequence of the dock from configuration to charging, which can be divided into two parts:

- **Steps 1–8: Prerequisite configuration** (completed once during deployment, no need to repeat for each charging)
  - Step 1 sets the **third-party dock mode**: Set the Parameter Configuration `third_dock_work_mode` to 1. See <a href="../../api-reference/dock/thing-model.html" target="_blank">Parameter Configuration</a> for details.
  - Step 3 sets the network / cloud / image transmission configuration. See <a href="../../api-reference/dock/dock-config.html" target="_blank">Dock Configuration</a> for details.
  - Step 5 sets the **base station work mode**: Set the Parameter Configuration `station_work_mode` to external dock mode. See <a href="../../api-reference/dock/thing-model.html" target="_blank">Parameter Configuration</a> for details.
  - Step 7 queries whether the drone is in place: Parameter Configuration `drone_in_dock`. See <a href="../../api-reference/dock/thing-model.html" target="_blank">Parameter Configuration</a> for details.
- **Steps 9–21: Charging process** (the start / stop charging on this page, including information acquisition and air conditioning control during the charging process).



:::tip Note:
This diagram only illustrates the charging process. Drone power on / power off (`drone_open` / `drone_close`) are independent operations that can be issued separately before or after charging as needed, and are not shown in the diagram.

**Air Conditioning Control Conditions**

- **Cooling start condition**: Battery temperature ≥ 35 ℃ or TX coil ≥ 80 ℃ or TX MOS ≥ 80 ℃ or RX coil ≥ 80 ℃.
- **Heating start condition**: Ambient temperature < 5 ℃ and battery temperature < 35 ℃ and TX coil < 80 ℃.
