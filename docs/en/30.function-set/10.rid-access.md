ESDK V2 supports connecting third-party RID/ADS-B receiver devices to the DJI Ground Station, reporting real-time drone identification and flight status data to DJI FlightHub 2, enabling unified aggregation and visual management of airspace awareness data. This section describes the RID device access process, reporting rate limits, and DJI FlightHub 2 visualization configuration.

:::tip Note:
RID is the first device type supported by ESDK V2. The `device_type` is fixed at 7 when reporting the capability set. More device types will be supported in the future, and the access framework will remain consistent.
:::

## Access Process

1. **MQTT Access and Authentication**: Concatenate the login information and connect to the DJI Ground Station Broker. RID devices must append the `@rid` suffix to the end of the username to lift the payload limit. For details, see <a href="../api-reference/mqtt.html" target="_blank">Access and Authentication</a>.
2. **Capability Set Reporting**: Report the device type and capability declaration via the state Topic. Data reporting can begin only after receiving result = 0. For details, see <a href="../api-reference/rid.html#capability-set-reporting" target="_blank">RID Data Reporting - Capability Set Reporting</a>.
3. **Data Reporting**: Cache detected RID / ADS-B targets and report them in batches. For details, see <a href="../api-reference/rid.html#rid-information-reporting" target="_blank">RID Information Reporting</a> and <a href="../api-reference/rid.html#ads-b-information-reporting" target="_blank">ADS-B Information Reporting</a>.

## Reporting Rate Limits

The DJI Ground Station imposes a message rate limit of 5 Hz on connected devices. Messages exceeding the limit will be blocked. The reporting of rid_infos and adsb_infos must follow these rules:

- Cache detected targets and report them in batches to avoid sending them one by one.
- Report rid_infos and adsb_infos every 2 seconds respectively, merging all targets cached during the period into the corresponding rid / adsb array and sending them together.
- The two event types are independent and are reported on their respective 2-second intervals.

## FlightHub 2 Visualization

After the RID device is successfully connected, you can view the RID devices mounted under the O4 Ground Station on the Device Maintenance page of DJI FlightHub 2:

<img src="https://terra-1-g.djicdn.com/71a7d383e71a4fb8887a310eb746b47f/esdk-v2/rid/device-maintenance-en.png" width="40%"/>

In the device list of DJI FlightHub 2, the connected RID devices will also be displayed under the O4 Ground Station:

<img src="https://terra-1-g.djicdn.com/71a7d383e71a4fb8887a310eb746b47f/esdk-v2/rid/flighthub-device-list-rid-en.png" width="80%"/>



The RID / ADS-B information reported by the device is forwarded to the cloud via the O4 Ground Station and can be viewed on DJI FlightHub 2. The configuration steps are as follows:

1. Enter the DJI FlightHub 2 project and navigate to **Airspace Safety** -> **Airspace Alert**.
2. Enable the **DJI O4 Ground Station** airspace alert.
3. In **Detection Type**, select the drone types for which you want to display alerts.
4. Set the alert distance threshold.

<img src="https://terra-1-g.djicdn.com/71a7d383e71a4fb8887a310eb746b47f/esdk-v2/rid/flighthub-o4-alert-settings-en.png" width="80%"/>

After configuration, DJI FlightHub 2 will display all RID / ADS-B drones within the alert distance threshold on the map:
- The **center** is determined by the gnss information in the reported content (i.e., the position of the reporting device itself);
- The **radius** is the configured **Alert Distance Threshold**;
- All RID / ADS-B drone targets within this circular range will be displayed on the map.

<img src="https://terra-1-g.djicdn.com/71a7d383e71a4fb8887a310eb746b47f/esdk-v2/rid/flighthub-rid-targets-on-map-en.png" width="80%"/>



:::tip Tip:
If DJI FlightHub 2 is not displaying targets, first confirm that the capability set report has returned result=0, and that rid_infos / adsb_infos are being reported normally according to the [Reporting Rate Limits](#reporting-rate-limits) without triggering the rate limit.
:::
