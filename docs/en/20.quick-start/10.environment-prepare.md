This section describes the development environment required for ESDK V2 access, including hardware devices, network connections, software dependencies, and Broker address retrieval.

## Development Devices

- One DJI O4 Ground Station, serving as the hosting platform for device access and data forwarding.
- One connected device or its development carrier (such as a Raspberry Pi or other Linux device) to run the access program.
- One switch or router to connect the O4 Ground Station and the connected device on the same local network.

## Hardware Connection

The O4 Ground Station provides two network ports: a LAN port and a WAN port, supporting the following two connection methods. For detailed descriptions of the network ports, see <a href="../basic-intro/hardware-port.html" target="_blank">Hardware Ports</a>.
:::tip Recommendation:
For initial access and debugging, it is recommended to use Method 1 (LAN port direct connection), as the Broker address is fixed and configuration is simplest.
:::

### Method 1: LAN Port Direct Connection

Connect the device directly to the O4 Ground Station's LAN port (right network port) via an Ethernet cable. The device IP must be in the `192.168.50.xx` subnet, and the Broker address is fixed at `192.168.50.10:1883`, requiring no additional lookup.

<img src="https://terra-1-g.djicdn.com/71a7d383e71a4fb8887a310eb746b47f/esdk-v2/network-topology/LAN-Port-en.svg" alt="Fig. ESDK device connected to O4 Ground Station via LAN port" />

### Method 2: WAN Port via Router

Connect both the device and the O4 Ground Station's WAN port (left network port) to the same router. The O4 Ground Station's IP is dynamically assigned by the router and can be obtained automatically via [Broker Address Retrieval](#broker-address-retrieval), or confirmed through DJI Pilot 2 Enterprise.

## Software Installation

The connected device needs to install the MQTT client dependency. For example, when developing based on mosquitto, run the following on Ubuntu/Raspberry Pi:

```bash
sudo apt install -y libmosquitto-dev
```

## Broker Address Retrieval

After the connected device is powered on, it can automatically obtain the O4 Ground Station's Broker address by listening for UDP broadcasts, eliminating the need to hard-code the IP.

### Overall Process

1. The connected device powers on and obtains an IP via DHCP on the network port.
2. The device listens on UDP port `18830`.
3. The O4 Ground Station broadcasts a packet through the network port approximately every 1 second.
4. After receiving the broadcast, the device parses the `ip` field and uses it to connect to MQTT (port `1883`).
5. If no broadcast is received, the device can fall back to the default address `192.168.50.10:1883` for direct connection.

### Broadcast Packet Format

The packet is a single line of ASCII text in a single UDP datagram. Fields are separated by `|`, and key-value pairs are separated by `=`. It contains no newlines or spaces, and the format is not JSON:

```
MQTTBRK|v=1|id=BMGDNAB0010122|name=O4_Ground_Station|ip=192.168.50.10|seq=32
```

| Field | Description |
|:---|:---|
| MQTTBRK | Fixed magic header. Devices use this to identify the packet. Packets that do not match this format should be ignored. |
| v | Protocol version, currently 1. Packets with unrecognized versions should be ignored. |
| id | The SN (unique ID) of the O4 Ground Station. Used to filter targets when multiple devices coexist. |
| name | Human-readable name, for display only. May be empty. |
| ip | The IP of the network port from which the broadcast was sent. The device uses this IP directly to connect to MQTT. |
| seq | Broadcast sequence number, incrementing from 0. When seq resets to 0, it indicates the O4 Ground Station has restarted, and the device should reconnect. |

:::warning Note:
The packet does not contain a port number. The Broker port is fixed at 1883.
:::

### Listening Parameters

| Item | Configuration |
|:---|:---|
| Protocol | UDP |
| Port | 18830 |
| Bind Address | `0.0.0.0` (Must bind to the wildcard address; binding to a specific network interface may cause some broadcasts to be missed) |
| Socket Option | `SO_REUSEADDR=1` (Must be set before bind) |
| Receive Buffer | >= 4096 bytes |

### Command-Line Verification

After the device is powered on and connected to the same subnet, you can use tcpdump to verify that broadcasts are reaching the device:

```bash
sudo tcpdump -i any udp port 18830 -A
```

Under normal conditions, the terminal will continuously output packet content containing `MQTTBRK|v=1|id=...|name=...|ip=...|seq=...`.
