ESDK V2 provides a sample project that demonstrates how third-party dock and RID devices access the DJI Ground Station, report capability sets, and call functional interfaces. This section describes how to obtain and build the sample project.

The SDK release package is self-contained. After extracting it, you can build it directly with CMake. The build process does not require a code generator, Python, or network access.

## Get the Code

You can clone the sample project from GitHub:

```bash
git clone https://github.com/dji-sdk/Edge-SDK-V2-Demo
```

If you use the SDK release package, extract it and enter the `edge-sdk-2.0.0/` directory before running the following commands.

## Environment Dependencies

Install the dependencies according to the target platform:

| Scenario | Dependencies |
|:---|:---|
| Host build (x86_64) | CMake (≥ 3.14), C compiler, libmosquitto, OpenSSL |
| aarch64 cross-compilation | CMake (≥ 3.14), C compiler, `gcc-aarch64-linux-gnu` |

On Ubuntu / Debian, run the following commands:

```bash
sudo apt install -y cmake build-essential libmosquitto-dev libssl-dev
sudo apt install -y gcc-aarch64-linux-gnu
```

`libuuid` is optional. If `uuid-dev` is installed, `bid` / `tid` use standard UUIDs. If it is not installed, the SDK automatically falls back to generating IDs from the device SN and a counter.

## Fill In Credentials

For how to obtain `app_id`, `app_key`, and `app_license`, see <a href="./dev-workflow.html#application-registration" target="_blank">Development Workflow Overview - Application Registration</a>.

Developer credentials can be configured in either of the following ways:

1. **Pass them as CMake variables (recommended)**: Pass `DOCK_APP_ID`, `DOCK_APP_KEY`, `DOCK_APP_LICENSE`, and other parameters at build time. During the CMake configure phase, `dock_app_info.h` is generated from `config/dock_app_info.h.in`.

   ```bash
   cmake -B build \
     -DDOCK_APP_ID=xxx -DDOCK_APP_KEY=xxx -DDOCK_APP_LICENSE=xxx \
     -DDOCK_APP_NAME=xxx -DDOCK_DEVICE_SN=your device identifier (device_id)
   ```

2. **Manually modify the template file**: Before building, modify the placeholder values in `config/dock_app_info.h.in`. During the CMake configure phase, `dock_app_info.h` is generated from this template.

:::tip Note:
In the protocol, `device_id` is the device's unique identifier. The sample project uses the device SN as `device_id` by default, so the related CMake variables are named `DOCK_DEVICE_SN` / `DOCK_RID_SN`.
:::

Common CMake variables are as follows:

| CMake Variable | Description | Default Value |
|:---|:---|:---|
| DOCK_APP_ID | Application ID | `your_app_id` |
| DOCK_APP_KEY | Application key | `your_app_key` |
| DOCK_APP_LICENSE | Application license | `your_app_license` |
| DOCK_APP_NAME | Application name | `your_app_name` |
| DOCK_DEVICE_SN | Dock (dt5) device identifier (`device_id`) | `dock_sn_demo` |
| DOCK_RID_SN | RID (dt7) device identifier (`device_id`) | Automatically derived when empty |
| DOCK_BROKER_FALLBACK_IP | Broker fallback address used when UDP discovery fails | `192.168.50.10` |
| DOCK_BROKER_PORT | Broker port | `1883` |

:::warning Note:
Do not commit real developer credentials to the code repository.
:::

### Configure the RID Device Identifier

The MQTT account `"<app_id>_esdk_<device_id>"` is also used as the MQTT `client_id` and the device segment in Topics. In the sample project, `DOCK_DEVICE_SN` / `DOCK_RID_SN` are filled into `<device_id>` in the protocol. If the dock (dt5) and RID device (dt7) use the same `device_id`, the device that connects later is rejected, usually with `CONNACK rc=5 (not authorised)`.

The RID device identifier is configured as follows:

1. If `DOCK_RID_SN` is empty and both dock and RID are built, the RID device `device_id` is automatically derived as `<DOCK_DEVICE_SN>_rid`.
2. To use an independent RID device identifier, explicitly pass `-DDOCK_RID_SN=your-rid-device-identifier`.
3. When building RID only (`-DEDGE_DOCK_ENABLE_DOCK=OFF`), `DOCK_DEVICE_SN` is used as the RID device `device_id` and the `_rid` suffix is not appended.

The configure phase prints the final device identifiers. Use the following logs to confirm the configuration:

```text
[edge-sdk] device SNs: dt5=... dt7=...
[edge-sdk] device SN: dt7=... (RID-only build)
```

### Override Configuration at Runtime

To point the same build output to another device identity or Broker, use environment variables. Rebuilding is not required:

```bash
DOCK_DEVICE_SN=xxx DOCK_RID_SN=yyy DOCK_BROKER_IP=192.168.50.10 DOCK_BROKER_PORT=1883 ./build/dock_cli
```

## Build

The project supports two build methods, which produce the same result. Choose either one.

### Method 1: Use the build.sh Script

The script wraps common parameters. Host builds and cross-compilation use independent output directories, so their caches do not affect each other:

```bash
./build.sh              # host build (x86_64), output in build/
./build.sh --cross      # aarch64 cross-compilation, output in build-aarch64/
./build.sh -c           # clear the corresponding build directory and reconfigure
./build.sh -j 8         # specify the concurrency level
```

### Method 2: Use CMake Directly

```bash
cmake -B build && cmake --build build -j
```

The release package contains an `sdk/` snapshot. The top-level `CMakeLists.txt` automatically uses the static snapshot and does not run code generation.

## Build Output

After the build is complete, the output is in the `build/` (host) or `build-aarch64/` (cross-compilation) directory:

| Output | Description | Build Condition |
|:---|:---|:---|
| dock_quickstart | Minimal sample used to verify the device access link | `EDGE_DOCK_ENABLE_DOCK=ON` |
| dock_sample | Dock (dt5) single-device interactive sample, used to debug dock functions | `EDGE_DOCK_ENABLE_DOCK=ON` |
| rid_sample | RID (dt7) single-device interactive sample, used to debug RID / ADS-B reporting | `EDGE_DOCK_ENABLE_RID=ON` |
| dock_cli | Full-feature interactive sample. Select a device identity first, then enter the corresponding function menu | `EDGE_DOCK_ENABLE_DOCK=ON` and `EDGE_DOCK_ENABLE_RID=ON` |

After connection succeeds, `dock_sample`, `rid_sample`, and `dock_cli` automatically report the capability set and wait for the acknowledgement.

For how to run them, see <a href="./run-sample.html" target="_blank">Run Sample</a>.

## Build Only One Device Type

If the device supports only one of the dock or RID types, you can disable the build of the other device type to reduce the output size. Source code and protocol code for the disabled device type are not compiled:

```bash
cmake -B build -DEDGE_DOCK_ENABLE_DOCK=ON  -DEDGE_DOCK_ENABLE_RID=OFF   # build the dock only (dt5)
cmake -B build -DEDGE_DOCK_ENABLE_DOCK=OFF -DEDGE_DOCK_ENABLE_RID=ON    # build RID only (dt7)
```

| Option | Corresponding Device | Function | Corresponding Sample |
|:---|:---|:---|:---|
| EDGE_DOCK_ENABLE_DOCK | Dock (dt5) | Takeoff and landing coordination, power-on and charging, dock configuration | `dock_quickstart`, `dock_sample` |
| EDGE_DOCK_ENABLE_RID | RID (dt7) | RID / ADS-B surveillance reporting | `rid_sample` |

The two options cannot be disabled at the same time. Common capabilities such as session, discovery, and authentication are always compiled in. `dock_cli` is generated only when both options are enabled.

## Cross-Compile to aarch64

Run the following commands to cross-compile aarch64 output:

```bash
./build.sh --cross
file build-aarch64/dock_quickstart
```

The `file` command output should contain `ELF ... ARM aarch64`.

Cross-compilation uses the headers and prebuilt OpenSSL / libmosquitto libraries in `third_party/aarch64-linux-gnu/`, and automatically uses the `cmake/toolchain-aarch64.cmake` toolchain file. Before building, install `gcc-aarch64-linux-gnu`.

When deploying to the target board, the executable RPATH is `$ORIGIN/../lib`. Place the executable files and dependency libraries as follows:

```text
/opt/edge-sdk/
├── bin/dock_quickstart
└── lib/          # copy third_party/aarch64-linux-gnu/lib/*.so here
```

For temporary verification, you can also specify the dependency library directory through `LD_LIBRARY_PATH`:

```bash
LD_LIBRARY_PATH=<so-directory> ./dock_quickstart
```

### Statically Link Dependency Libraries

To make the output independent of the `libssl`, `libcrypto`, and `libmosquitto` dynamic libraries, enable `EDGE_SDK_STATIC_DEPS` for static linking:

```bash
bash third_party/build-static-deps.sh aarch64-linux-gnu

cmake -B build-aarch64 -DEDGE_SDK_STATIC_DEPS=ON \
  -DCMAKE_TOOLCHAIN_FILE=cmake/toolchain-aarch64.cmake && cmake --build build-aarch64 -j

readelf -d build-aarch64/dock_quickstart | grep NEEDED
```

If static linking succeeds, the `readelf` output should not contain `libssl`, `libcrypto`, or `libmosquitto`. glibc remains dynamically linked. Fully static linking glibc is not recommended.
