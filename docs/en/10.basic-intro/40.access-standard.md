This section defines the technical standards that third-party devices must meet to access ESDK V2, including network communication, capability set declaration, and message constraints.

## Network and Communication

- Devices must support Ethernet and be deployed on the same local network as the DJI Ground Station.
- Devices must support the MQTT protocol and connect to the Broker provided by the DJI Ground Station, with the port fixed at `1883`.
- Devices must use `app_id`, `app_key`, and `app_license` to complete MQTT authentication. For the concatenation rules, see <a href="../api-reference/mqtt.html#login-information" target="_blank">Access and Authentication - Login Information</a>.

## Capability Set and Topics

- After connecting, devices must report the capability set once, declaring their type and supported capabilities via `device_type`.
- Devices must follow the unified Topic rules for subscribing and publishing. The `{client_id}` format is `{app_id}_esdk_{device_id}`.
- Devices should subscribe to the `state_reply` and `error` Topics to receive capability set reporting results and error notifications.

## Message Rate and Payload

The DJI Ground Station imposes the following restrictions on messages from connected devices:

| Item | Limit |
|:---|:---|
| Message Rate | 5 Hz |
| Single Message Payload | 2048 bytes |

When the limit is exceeded, the DJI Ground Station will block the message and notify the device via the `error` Topic.

:::tip Note:
Some devices have large single-message payloads (e.g., RID devices can reach approximately 20 KB). The limit can be lifted through <a href="../api-reference/rid.html#payload-extension" target="_blank">Payload Extension</a>.
:::
