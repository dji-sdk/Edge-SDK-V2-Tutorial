This section summarizes the key terms and abbreviations involved in the ESDK V2 development documentation, helping developers quickly understand the proprietary terms and technical concepts used throughout the documentation.

## Platform and Devices

| Term | Full Name | Description |
|:---|:---|:---|
| O4 Ground Station | DJI O4 Ground Station | DJI Ground Station product, the hosting platform for third-party device access in ESDK V2. |
| FlightHub 2 | DJI FlightHub 2 | DJI enterprise drone management cloud platform, which can display RID / ADS-B target information. |
| Third-Party Dock | Third-Party Dock | Refers to non-DJI dock devices that access ESDK V2, working with the O4 Ground Station to implement capabilities such as drone power-on/charging and takeoff and landing coordination. In the capability set report, device_type = 5. |
| RID | Remote ID | Remote identification, a technology used to identify and track drones. In the capability set report, device_type = 7.|
| ADS-B | Automatic Dependent Surveillance-Broadcast | A type of aircraft surveillance technology that obtains information such as the position and speed of surrounding aircraft. |
| dt5 | Device Type 5 | Abbreviation for `device_type = 5`, indicating a third-party dock device. |
| dt7 | Device Type 7 | Abbreviation for `device_type = 7`, indicating an RID device. |
| gateway_sn | Gateway Serial Number | The serial number of the O4 Ground Station (gateway). |
| device_id | Device ID | The unique identifier of the accessing device, used to concatenate the username / ClientID in the MQTT login information, in the format `{app_id}_esdk_{device_id}`. The ESDK V2 sample project uses the device SN as `device_id` by default. |

## Access and Protocol

| Term | Full Name | Description |
|:---|:---|:---|
| MQTT | Message Queuing Telemetry Transport | A lightweight publish/subscribe messaging protocol. ESDK V2 uses MQTT to implement communication between devices and the DJI Ground Station. |
| Broker | MQTT Broker | The MQTT message broker server, responsible for receiving, routing, and distributing messages. The O4 Ground Station has a built-in MQTT Broker for accessing devices to connect to. |
| Topic | MQTT Topic | The topic identifier of MQTT messages. Devices send and receive data by subscribing to and publishing different Topics. |
| QoS | Quality of Service | The Quality of Service level of MQTT, which defines the reliability guarantee of message transmission. ESDK V2 uses QoS 0 and QoS 1. |
| CONNACK | Connection Acknowledgement | The MQTT connection acknowledgement packet. Return code 0 indicates a successful connection, and 5 indicates authentication failure. |
| Capability Set | Capability Set | The device type and capability declaration that a device must report after access. The DJI Ground Station identifies and processes device data accordingly. |
| device_type | Device Type | The device type identifier, declared in the capability set report. A third-party dock is 5, and an RID device is 7. A single device can only declare one device_type at a time, not both simultaneously; it cannot be accessed under multiple identities at the same time. |
| service / reply / event | Service / Reply / Event | The three roles of ESDK V2 message interaction: service is the issued service request, reply is the corresponding response, and event is the event notification actively reported by the device. |
| bid / tid | Business ID / Transaction ID | bid is the business ID, used to identify a complete business process; tid is the transaction tracking ID, used to associate a request with its corresponding reply. When troubleshooting protocol integration issues, you can compare the tid to confirm whether the request and reply are paired. |
| Thing Model / TSL | Thing Specification Language | A model definition language that describes device parameters and capabilities. Third-party docks set / get dock configuration parameters through the thing model interface. |
| OSD | On-Screen Display | The push channel for read-only thing-model parameters. The dock's real-time status (read-only properties such as battery, charging, and coil) is actively pushed by the gateway through the OSD Topic; developers only need to read them. |

## Hardware and Charging

| Term | Full Name | Description |
|:---|:---|:---|
| TX Coil / RX Coil | TX Coil / RX Coil | The transmitting coil (dock side, TX) and receiving coil (drone side, RX) of wireless charging. The two couple to complete wireless charging. |
| ACDC | AC-DC Module | The AC-to-DC power supply module in the wireless charging system, which provides power to the TX board and charging circuit. |
| SDR | Software Defined Radio | Software Defined Radio; here it refers to the image transmission link module between the drone and the O4 Ground Station. |
| CAN-LAN | CAN to LAN Adapter | An adapter that converts a CAN bus to a local area network, used for communication between the wireless charging module (ACDC) and the O4 Ground Station. |
| Marker | Marker | The pattern identifier on the dock landing pad for the drone to recognize and locate, used to assist precision landing. |

## Flight and Positioning

| Term | Full Name | Description |
|:---|:---|:---|
| Home Point / Alternate Landing Point | Home Point / Alternate Landing Point | The home point is the return point recorded when the drone takes off; the alternate landing point is the backup landing location in abnormal situations, which only needs to be set once during dock deployment. |
| GNSS | Global Navigation Satellite System | Global Navigation Satellite System, including GPS, BeiDou, etc., used for device positioning. |
| ICAO | International Civil Aviation Organization | The International Civil Aviation Organization. ADS-B uses a 24-bit ICAO address code to identify aircraft. |
